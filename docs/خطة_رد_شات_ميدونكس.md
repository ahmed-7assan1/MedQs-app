## 1. المشكلة الحالية

**الـ rendering pipeline الحالي يعيد معالجة كل النص كل إطار (16ms) أثناء الـ streaming:**

```
استلام chunk → RAF → setThreads → React render → DrQMessage
  ├── 3 useMemo (regex على content كامل) ← questions, flashcards, cleaning
  ├── Image extraction: 2 matchAll على content كامل
  ├── react-markdown (يبني AST من markdown كامل) + remarkGfm
  └── React reconciliation ← DOM update كامل
```

**المشكلات:**
- 3 regex passes على كل النص كل إطار
- react-markdown يعيد بناء AST من 0 كل إطار
- كل المكونات re-render لأن `content` يتغير كل إطار
- `React.memo` على DrQMessage لا ينفع—لأن props.message يتغير
- إضافة نوع محتوى جديد يتطلب تعديل 4-5 أماكن

## 2. الحل: Structured Output + NDJSON

بدل ما الـ AI يكتب markdown بعلامات `:::question`، يخرج JSON blocks—كل block في سطر مستقل (NDJSON):

```
{"type":"paragraph","text":"شرح Atrial Fibrillation..."}
{"type":"heading","level":2,"text":"Causes"}
{"type":"paragraph","text":"Common causes include hypertension..."}
{"type":"table","headers":["Drug","Dose"],"rows":[["Aspirin","100mg"]]}
{"type":"question","questionType":"MCQ","body":"What is...","choices":[...],"answer":"A"}
{"type":"flashcard","front":"Q?","back":"A"}
```

**لماذا NDJSON وليس JSON array واحد:**
- كل سطر مستقل—يقبل الـ parse فور وصوله (streaming-friendly)
- لو سطر فشل، باقي السطور لا تتأثر
- bracket-depth parser يتعامل مع multi-line JSON لو احتاج
- النص العادي (غير JSON) يعامل كـ paragraph—safe fallback

## 4. Streaming Pipeline — بالتفصيل

```
API Stream (SSE chunks)
        │
        ▼
streamGemini / streamOpenAICompat
  • يبني accumulated text (full)
  • call: onChunk(full)
        │
        ▼
RAF-batched flushToState()
  • pendingContentRef.current = accumulated
  • requestAnimationFrame(flushToState)
        │
        ▼
parseStreamingBlocks(accumulated)    ← NEW
  • bracket-depth parsing
  • كل complete JSON object → parse + Zod validate → block
  • النص العادي → ParagraphBlock
  • الـ incomplete (آخر bracket غير مغلق) → partialLine
        │
        ▼
extractPlainText(blocks)  ← NEW
  • يمر على كل البلوكات ويستخرج النص
  • paragraphs, headings → نصوص فقط
  • questions, flashcards → يستثنى (لأنهم interactive مو للـ TTS)
  • النتيجة: plain text نظيف بدون JSON
        │
        ▼
setThreads()
  • message.content = plainTextFromBlocks   (نص نظيف ← TTS, model context)
  • message.structuredContent = blocks      (للـ rendering)
  • message.partialLine = incomplete_text   (للـ streaming)
        │
        ▼
React render → DrQMessage → StructuredContentRenderer
  • blocks المكتملة → React.memo → لا re-render
  • partialLine فقط → StreamingText → re-render بسيط
```

### الـ Parser (الخوارزمية الأساسية):

يتكون من خطوتين:

#### 4.1. parseStreamingBlocks — تحويل النص الخام إلى بلوكات

```typescript
function parseStreamingBlocks(accumulated: string): {
  blocks: ContentBlock[];
  partialLine: string;
} {
  const completeObjects: string[] = [];
  let depth = 0;
  let inString = false;
  let current = '';

  // تمرير 1: bracket-depth (يتعامل مع newlines داخل JSON strings)
  for (const char of accumulated) {
    if (char === '"' && !current.endsWith('\\')) inString = !inString;
    if (!inString) {
      if (char === '{') depth++;
      if (char === '}') depth--;
    }
    current += char;
    if (depth === 0 && current.trim()) {
      completeObjects.push(current.trim());
      current = '';
    }
  }

  const partialLine = current;  // اللي incomplete

  // تمرير 2: JSON.parse + Zod validate لكل complete object
  for (const objStr of completeObjects) {
    if (objStr.startsWith('{')) {
      try {
        const parsed = JSON.parse(objStr);
        const validated = contentBlockSchema.parse(parsed);
        blocks.push(validated);
        continue;
      } catch {}
    }
    // نص عادي أو JSON فاشل → paragraph
    if (objStr.trim()) {
      blocks.push({ type: "paragraph", text: objStr.trim() });
    }
  }

  return { blocks, partialLine };
}
```

#### 4.2. extractPlainText — استخراج النص النظيف للـ TTS والتخزين

```typescript
function extractPlainText(blocks: ContentBlock[]): string {
  return blocks
    .map(block => {
      switch (block.type) {
        case "paragraph": return block.text;
        case "heading": return block.text;
        case "list": return block.items.join("\n");
        case "blockquote": return block.text;
        case "image": return block.alt || "";        // الوصف فقط
        case "question": return "";                    // interactive—لا يقرأ
        case "flashcard": return "";                   // interactive—لا يقرأ
        case "checklist": return block.title || "";    // العنوان فقط
        case "table":
          // headers + rows كجملة
          return [block.headers.join(", "), ...block.rows.map(r => r.join(", "))].join("; ");
        default: return "";
      }
    })
    .filter(Boolean)
    .join("\n\n");
}
```

## 5. Speed Strategy — 5 تقنيات

### 5.1. React.memo على كل بلوك (الأهم—فرق 70%)

كل بلوك ملفوف بـ `React.memo`، لذلك أثناء الـ streaming:
- البلوكات المكتملة لا تتغير مرجعياً → لا re-render
- فقط `partialLine` يتغير كل إطار
- الحالي: الـ `ReactMarkdown` AST + 3 regex كل إطار = 8-12ms
- الجديد: بلوك واحد + bracket-depth pass = 1-3ms

### 5.2. Registry Map بدل Switch

```typescript
const BLOCK_REGISTRY: Record<string, React.ComponentType<any>> = {
  paragraph: ParagraphBlock,
  heading: HeadingBlock,
  table: TableBlock,
  code: CodeBlock,
  question: QuestionBlock,
  // ... إضافة نوع جديد = سطر واحد
};

function BlockRenderer({ block }: { block: ContentBlock }) {
  const Component = BLOCK_REGISTRY[block.type];
  return Component ? <Component block={block} /> : <UnknownBlock />;
}
```

### 5.3. Incremental Rendering (للردود 30+ بلوك)

عند انتهاء الـ streaming، نرندر البلوكات تدريجياً بدفعات 5-10 كل إطار عشان ما يسببش jank:

```typescript
function useIncrementalRender(blocks: ContentBlock[], step = 5) {
  const [visible, setVisible] = useState(step);
  useEffect(() => {
    if (visible >= blocks.length) return;
    const id = requestAnimationFrame(() =>
      setVisible(p => Math.min(p + step, blocks.length))
    );
    return () => cancelAnimationFrame(id);
  }, [visible, blocks.length]);
  return blocks.slice(0, visible);
}
```

### 5.4. Web Worker للـ Parsing (للرفع)

الـ bracket-depth parse + JSON.parse في Worker لتحرير main thread، لكن هذا للرفع بعد الأساسيات.

### 5.5. Skip Zero-Content Renders

أثناء الـ streaming ما بين الـ chunks، إذا `partialLine` فارغ، نرجع `null` بدل re-render.

## 6. تحليل السرعة—قبل وبعد (per 16ms frame)

| الخطوة | الحالي (markdown) | المقترح (SOR) | الفرق |
|--------|------------------|---------------|-------|
| **Regex** | 3 passes على n lines | split + bracket-track | ~3x أسرع |
| **JSON parse** | فقط لو فيه `:::` markers | كل complete line | مشابه |
| **AST build** | react-markdown AST | **مفيش** | غير موجود |
| **Re-render scope** | DrQMessage + ReactMarkdown + كل المحتوى | `partialLine` فقط | كثير أسرع |
| **DOM update** | استبدال كل النص | إضافة بلوك واحد أو نص | أسرع |
| **Total** | 8-12ms | 1-3ms | 3-4x أسرع |

## 10. التأثير على الـ Voice Mode (TTS)

### 10.1. المشكلة

الحالي: `message.content` يحتوي على markdown + `:::question {JSON} :::` markers. TTS يقرأ هذا النص حرفياً—فيشتمل على `:::` والـ JSON (أسوأ: يقرأ "colon colon colon question open brace...").

المقترح: `message.content` = plain text مستخرج من البلوكات (نظيف 100%).

```
Raw API stream:  {"type":"paragraph","text":"Hello"}\n{"type":"paragraph","text":"World"}
                         │
                         ▼
message.content = "Hello\n\nWorld"        ← plain text ← TTS يقرأه صح
message.structuredContent = [blocks...]   ← للـ UI
```

### 10.2. تحسين: Block-Level TTS

الحالي: TTS ينتظر الـ response كامل (`!last.isStreaming`) قبل ما يبدأ.

```
API: [...][...][...][complete!]
                      └──→ TTS starts here ← المستخدم ينتظر
```

بعد: TTS يبدأ مع أول بلوك مكتمل (قبل نهاية الـ streaming).

```
API: [{"type":"paragraph","text":"Hello"}][...][...]
     └──→ TTS starts here ← أسرع بزمن بداية الصوت
```

**التأثير:** Time-to-First-Audio يقل بشكل ملحوظ. المستخدم يسمع الرد وهو لسه بيجيله.

### 10.3. التغييرات المطلوبة

- إضافة `extractPlainText()` في الـ parser (موجودة في 4.2)
- تعديل Auto-TTS effect في `MedOneXChat.tsx`:
  - بدل `!last.isStreaming`، نتحقق من `last.structuredContent?.length > 0`
  - لكل بلوك جديد، نمرر نصه لـ TTS

### 10.4. الخلاصة

| الجانب | الحالي | المقترح |
|--------|--------|---------|
| **ما يقرأه TTS** | `:::` markers + JSON + markdown | Plain text فقط (نظيف) |
| **وقت بداية TTS** | بعد انتهاء الـ streaming | مع أول بلوك مكتمل |
| **جودة الصوت** | "colon colon colon" (سيء) | كلام طبيعي (ممتاز) |
| **الإحساس** | ينتظر ثم يسمع فجأة | يسمع تدريجياً مع الكتابة |
